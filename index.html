The problem

Your agent just ran two hundred commands. You got a diff and a feeling.

A diff hides the run

A diff shows what ended up on disk. It does not show the files the agent read, the commands it ran or the tests it deleted along the way.

Risk lands before review

By the time you read the log, the force push, the .env read or the rm -rf has already happened.

Nobody can say what it cost

Tokens are spread across models and steps. It is hard to tell which step used the budget, or whether a cheaper model would have done.

How it works

Record. Receipt. Guard. Review.

RunLedger reads the session logs your agent already writes. No wrapper, no proxy, nothing between you and your tools.

Point RunLedger at a folder where an agent ran. It finds the newest session and parses every step: tool calls, files, models and token usage.

Stop it before it runs

A Claude Code hook checks every tool call against the same rules as the receipt. It denies, asks or allows before anything executes.

rm -rf /deny
cat .envask
npm testallow

Ask for a second opinion

Optionally, --review has Claude mark each finding as confirmed, false positive or uncertain. The rule-based score never changes. In CI, --fail-on 60 fails the job on high scores.

Real-time guard

Block the command, not the post-mortem.

The guard is a Claude Code hook. Before each tool call runs, it decides deny, ask or allow. Pick a call to see the default policy at work.

runledger guardPreToolUse hook
tool: Bash
rm -rf /
denycommand · high

Recursive force delete (rm -rf)

The call is blocked. Claude Code is told why and the command never runs.

Install with runledger guard install, remove with runledger guard uninstall. If the guard cannot evaluate a call it fails open by default, or closed if you set it. Guard docs

GitHub Action

A receipt on every pull request.

One sticky comment per pull request, updated on every push. Add a threshold and the job fails when a run is too risky.

name: RunLedger receipt
on: pull_request
permissions:
  contents: read
  pull-requests: write
jobs:
  receipt:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: kodji7202-code/runledger@v0.5.0
        with:
          fail-on: "60"  # fail at 60 or above

Commit the sessions you want reviewed to .runledger/sessions/. Review them first: a session file can contain secrets. Action docs

Self-host

A team server you run yourself.

Developers push receipts, the team reads them in one dashboard. The server uses only the Python standard library and a single SQLite file, with a Docker Compose setup for HTTPS.

  • Dashboard
  • API keys with roles
  • Audit log
  • Approvals
  • Slack and webhooks
  • Team budgets
  • Compliance exports
  • Retention and backups

Self-hosting guide

  1. runledger team create myteam --db runledger.dbcreate the team, prints its API key once
  2. runledger serve --db runledger.dbstart the server on 127.0.0.1:8787
  3. open http://127.0.0.1:8787/?key=YOUR_KEYsign in to the dashboard once
  4. export RUNLEDGER_SERVER=http://127.0.0.1:8787on each developer's machine, with RUNLEDGER_API_KEY
  5. runledger push --user "ana@example.com"push the latest run

FAQ

Questions, answered.

Does my code leave my machine?
Not by default. receipt, list and the guard run locally, and RunLedger has no telemetry. The network is used only when you ask: pushing to your team server, webhooks you set, the GitHub API in the Action, and the Anthropic API when you use --ai or --review.
What is in a receipt?
The first prompts, each step (the first line of a command, file paths, line counts, the model, tokens and estimated cost), the risk findings with reasons, and the files changed. It does not include file contents or command output, only test pass and fail counts.
Are secrets masked?
Known token formats, assignments such as API_KEY=..., --token flags and passwords in URLs are masked in receipts, pushes and PR comments. Masking is pattern-based, so an unusual secret can get through. Treat a receipt like the transcript it came from.
Which agents work?
Claude Code is stable. Codex CLI, Factory Droid and Aider are in beta. Any other agent can write the open RunLedger format and get the same receipts and risk scores. The real-time guard currently hooks into Claude Code only.
What does the guard block?
By default it denies hardcoded secrets written to files and high-severity commands such as rm -rf, force pushes, curl | sh, DROP TABLE, npm publish and kubectl apply. It asks before sudo, reading a .env file, writing outside the project or deleting a test. You can change the policy in ~/.runledger/config.json.
Is the AI review required?
No. The risk score comes from deterministic rules. --review and --ai are opt-in and send redacted session content to Anthropic using your own API key.
Are the cost numbers real?
They are estimates from public API list prices for the tokens used, not a bill. Read them as what the run would cost on the API.
Is it open source?
Yes. RunLedger is licensed under Apache-2.0, including the self-hosted team server. No account is needed. --ai and --review are optional and use your own Anthropic API key.
How do I remove it?
Run runledger guard uninstall (add --global for every project) to remove the hook and keep your other Claude Code settings, then pip uninstall runledger-ai.
