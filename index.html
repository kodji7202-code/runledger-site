How it works

Agents now ship code. Nobody reads the transcript.

Runs happen unsupervised, logs run to thousands of lines, and risk hides in the details. RunLedger records each run, explains it, and lets you decide.

  1. 01

    Record

    RunLedger reads the session log your agent already writes: files read and written, commands, web requests, model and tokens for every step. It stays on your machine.

  2. 02

    Explain & score

    Each step gets a plain-language summary. The run gets a rule-based risk score from 0 to 100, with the reason behind every point.

  3. 03

    Decide

    Share the receipt with a teammate, guard risky commands before they run, or send sensitive actions for approval.

Real-time Guard

It stops risky commands before they run.

A Claude Code PreToolUse hook checks each action first. Dangerous commands are blocked. Sensitive ones ask first, either in Claude Code or as an approval request on your team server.

CLI On your machine or in your CI

Free and open source. No account needed.

  • Run receipts

    Every run as HTML, Markdown or JSON: files changed, commands and web requests, explained in plain language.

  • Real-time Guard

    A Claude Code PreToolUse hook that denies or asks before a risky call runs. Start in monitor mode to see what it would stop.

    $ rm -rf ./build ~/deny
    $ sudo npm i -g xask
    $ npm testallow
    enforcemonitorfail-open

  • Risk score with reasons

    Flags secrets, hardcoded keys, deleted or skipped tests, rm -rf, force-push, sudo and curl | sh, in Bash and PowerShell.

  • Cost & tokens

    Tokens and estimated cost for every step and model, so you see where a run's spend went.

  • GitHub PR comments

    One sticky receipt comment per pull request, and a failed job above the risk threshold you set.

  • Per-project policies

    Rules per repository in .runledger.json. A project can make the guard stricter, never looser.

  • Quality score & cost tips

    A grade from A to F with the signals behind it, plus tips that estimate what you could save.

  • AI risk review

    Opt-in --review: Claude marks each finding as confirmed, false positive or uncertain. The score stays rule-based.

Install

Your first receipt in two commands.

Free and open source. No account, no dependencies, and it works offline. Receipts stay on your machine until you choose to push them.

  • Python 3.9 or later. Tested in CI on Linux, macOS and Windows.
  • Run runledger list in a project folder to see its recent agent sessions.
  • Full walkthrough, including CI and a local team server: Quickstart · Guard docs

1 Install

$ pip install runledger-ai

Or as an isolated tool: pipx install runledger-ai or uv tool install runledger-ai

2 Receipt for your latest run

$ runledger receipt --open

Run it in the folder where you used the agent. The HTML receipt opens in your browser.

3 Optional: turn on the guard for Claude Code

$ runledger guard install

Adds a PreToolUse hook to this project's .claude/settings.json and keeps a backup. Use --global for every project.

FAQ

Questions, answered plainly.

Does my code leave my machine?

Not unless you ask it to. receipt, list and the guard run on your machine, and RunLedger has no telemetry. Data leaves only when you push a run to a team server, set Slack or webhook notifications, use the GitHub Action, or opt in to --ai or --review, which send parts of the session to the Anthropic API.

What exactly does a receipt record?

The first prompts, and for each step: the first line of the command (up to 120 characters), file paths and line counts, search patterns and URLs, the model, tokens and cost, plus the risk findings and their reasons. It does not contain file contents or command output, only test pass and fail counts. Known secret formats (API keys, tokens, passwords in KEY=… assignments, flags and URLs) are masked as [REDACTED]. Masking is pattern-based, so treat a receipt like the session it came from. The guard writes its decisions to .runledger/guard.log in the project. Add .runledger/ to your .gitignore.

Which agents and systems does it support?

Claude Code is stable. Codex CLI and Aider are in beta, and any agent can write the open RunLedger session format. The CLI needs Python 3.9 or later and is tested on Linux, macOS and Windows. The guard is a Claude Code hook, so it works with Claude Code only.

How is the risk score computed?

By fixed rules, so every point has a reason you can check. Each finding adds points by severity: 30 for high, 15 for medium, 5 for low. A repeat of the same finding adds a third. All medium findings together add at most 45 and all low findings at most 10, so many small findings cannot reach 100 on their own. The total is capped at 100. Below 25 is Low, below 60 is Medium, and 60 or more is High.

What about false positives?

Start the guard in monitor mode ("mode": "monitor" in ~/.runledger/config.json). It then logs what it would have blocked without stopping anything. Tune the rules in your user file or a project's .runledger.json. For receipts, the opt-in --review asks Claude to mark each finding as confirmed, false positive or uncertain, without changing the score.

How do I turn the guard off?

Run runledger guard uninstall in the project, or runledger guard uninstall --global if you installed it with --global. It removes only the guard hook from .claude/settings.json and saves the previous file as settings.json.bak. To remove the CLI, run pip uninstall runledger-ai.

Will the guard slow my agent?

The guard is a local check that takes milliseconds. By default it fails open: if it hits an internal error, Claude Code's normal permissions apply. Set "fail_closed": true if you would rather deny on errors.

How is cost computed?

From public Claude API list prices, applied to the token counts recorded for each step. It is an estimate, not an invoice. On a subscription you are not billed per token, so read it as what the run would cost on the API.

Where does team data live?

On the server you choose. The self-hosted team server stores pushed receipts in one SQLite file on your own machine or cloud, and keeps them until you delete them. For the hosted Team plan, we will publish where data is stored and for how long before it launches.

How is this different from LLM tracing tools?

Tracing and observability tools usually sit in front of your API calls and send traces to a service. RunLedger reads the session logs that coding agents already write, works offline, and focuses on what a reviewer needs: what changed, what it cost, and what looked risky. Its guard can also stop a tool call before it runs.
